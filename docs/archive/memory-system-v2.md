# Leap Agent 长期记忆 V2 设计说明

## 目标

在现有 `shortterm + preference` 的基础上，补一层真正参与回答的长期记忆：

1. 对话后抽取可复用事实、排障案例、工具经验和长期约束
2. 持久化到 PostgreSQL 事实源
3. 下一轮请求前按当前问题召回
4. 作为 system prompt 的一部分注入

这版先追求可维护和可验证，不把图增强、数据库治理、跨租户隔离一起塞进来。

## 参考 AGI-saber 的结论

AGI-saber 的长期记忆思路是完整的，但有几个明显问题：

1. 写入太偏向助手回复，容易把模型输出写成事实
2. 图层和长期记忆层耦合更重，治理成本高
3. 合并、淘汰、异步写入都比较激进
4. 主链路和更完整的上下文装配器存在脱节

所以 Leap Agent 的 V2 采用更保守的策略：

1. 长期记忆只在回复完成后异步使用 LLM 抽取，不再做规则写入
2. LLM 从整轮问答抽取可复用事实、排障案例和工具经验，并要求置信度阈值
3. 以 PostgreSQL 保存可治理字段和 embedding，文件仓储只保留为本地兜底
4. 只召回少量相关记忆，不把 prompt 撑爆

## 当前链路

### 写入

用户提问进入 chat 后：

1. 先走短期记忆和偏好记忆
2. 生成回答
3. 回复完成后异步写长期记忆

写入时只走异步 LLM 抽取：从整轮对话里提取系统事实、排障案例、工具经验和用户确认的长期结论。

偏好、回复语言、地域、默认时间范围、用户画像等内容交给偏好记忆模块，不在长期记忆里做规则兜底。

### 召回

下一轮请求前：

1. 用当前 query 做相似度召回
2. 结合重要性、时效性、类别偏置做排序
3. 取前 `memory.long-term.prompt-top-k` 条注入 prompt

召回相似度参考 AGI-saber 的双层策略：

1. 优先使用持久化在记忆条目里的 `embedding` 做 cosine 相似度
2. 当 embedding 不可用、生成失败或维度不一致时，用内容临时构建 TF 词频向量降级召回

TF 词表不单独持久化，启动恢复后可以从 `content` 重建；真正需要跨进程保存的是长期记忆条目本体和 embedding。

### 持久化

长期记忆仓储支持两种模式：

1. `repository: postgres`：推荐模式，PostgreSQL 作为事实源，保存完整条目、embedding、分类、重要性、置信度、版本和生命周期状态。
2. `repository: file`：本地 JSON 兜底，适合无数据库的快速编译或临时演示。

当前没有把长期记忆直接写入 Milvus。Milvus 更适合作为后续可选向量索引层，用 `memory_id` 回表 PostgreSQL 取完整事实；不建议让它承担合并、衰减、过期、审计等事务型治理。

### 注入

长期记忆以独立段落注入 system prompt，位置在：

1. 全局偏好之后
2. 短期记忆之前

这样能让全局约定优先于历史片段，但仍保留当前会话上下文。

## 数据结构

长期记忆条目包含：

1. `id`
2. `sessionId`
3. `category`
4. `content`
5. `tags`
6. `importance`
7. `confidence`
8. `source`
9. `embedding`
10. `createdAt`
11. `lastAccessed`
12. `version`
13. `status`

## 这版的取舍

保留：

1. 长期记忆的完整闭环
2. 明确的分类和调试视图
3. PostgreSQL 事实源，便于后续治理、迁移和审计
4. 轻量治理：写入达到阈值后执行衰减、近重复去重、相似合并和低价值过期淘汰

暂不做：

1. Neo4j 图增强
2. 多用户隔离
3. 工具参数自动补全
4. Milvus 长期记忆向量索引与图中心度保护钩子

## 验收标准

当前阶段只看：

1. 项目能编译通过
2. 长期记忆能被注入主对话链路
3. 调试接口能看到长期记忆快照
